# TipPool — Claude Code Guide

## What this app is

A mobile-first, no-build single-page web app for calculating and distributing a cash tip pool among restaurant/bar staff. **Goal:** at close, one person enters who worked and how much cash there is, and gets what each person takes home and which bills go in each envelope. Four tabs: **Home · Staff · Tips · Settings**. **Home** is first (where sessions open) and is **read-only** — nothing on it edits anything; until the shift is complete it shows the close-out checklist **Staff → Tips → Home**, and the input tabs end with Next buttons in that order. **Staff** and **Tips** are where things are entered and adjusted; **Settings** holds the sessions and app preferences. No server-side code, no build step, no npm install. ES modules served statically; styling is Tailwind v4's browser build, vendored at `vendor/tailwind-browser-4.3.3.js` (no CDN). Views are **Preact + htm** components (React API, no build), vendored at `vendor/preact-htm-3.1.1.js`.

**Unified pool model (v4):** there is no day/night mode split. Tips are entered into one or more *pools*; each pool has its own time window, role inclusion (Bar / Srv / Sup chips), and cash entry. **Shift types** (`shifts.js`, `meta.shiftType`): *Night* = one pool, whole shift. *Day* = **Day** (bar + servers, open → servers out) and **Mid** (bar only, servers out → bar out) — the edges are derived (`'srv'` / `'bar'`, see resolve) so the hand-over follows the floor. Either type can add **Party** pools: a private event's own tips over its own window, overlapping the floor pools, support tip-out on (a person in both gets both). Support staff included in a pool get a tip-out off the top (pool % — default 10 — of the total over the window hours, or a typed $/hr, × their hours); bartenders / servers share the rest by overlap hours.

```bash
npx serve .          # or
python3 -m http.server
# then open the served URL — ES modules require http, file:// won't work
```

PWA-ready: `manifest.json` + `icon-192.png` / `icon-512.png` / `apple-touch-icon.png` enable "Add to Home Screen." ## Architecture

One-way pipeline, pure compute, renderers read only the view model:

```
input event → App.* handler → store action mutates state
  → schedule (120ms debounce; structural changes immediate)
  → buildViewModel(state):
      resolveStaff → resolvePools → computeShares → bills → distribute
  → render(vm) per area → persist.save(state)
```

Blockers carry where they're fixed: `vm.blocked` (message) + `vm.blockedTab` (`'staff'` for resolveStaff errors / no named staff, `'tips'` for resolvePools errors / no cash; staff wins when both). Route on `blockedTab`, never by matching the message text.

### State shape (store.js)

```js
{
  meta: { date, shiftType },                               // 'night' | 'day'
  staff: [{ id, name, role, in, out, brk, brkAt, closerOverride }],   // ONE array, role is a field; brk = break hours ('0.5'), brkAt = when it began ('' = not placed)
  defaults: { global: {in, out}, byRole: {bartender, server, support} },
  pools: [{ id, label, kind, window: {start, end}, roles: {bartender, server},   // kind: night|day|mid|party|''; window edge: '' | '3.5' | 'srv' | 'bar'
            includeSupport, cash: { entryMode: 'mixed', billCounts, netTotal, restMode, adjust } }],  // counted bills + rest ('rest') or total incl. counted ('total') + register over/short
  overrides: { bonuses: { staffId: $ } },                  // manual remainder split (persisted)
  settings: { allRoles, multiPool, clock24, size, theme, shiftTimes, amFrom, show, stacks },  // app prefs; shiftTimes = last default times per shift type; show = { timelines, bestBills, working } (the page drawers' Show switches)
  ui: { activeTab, selectedPool },
}
```

Raw input strings are stored as typed; `''` means "inherit a default." All parsing/resolution happens in `resolve.js` at compute time.

### Time model

Entry is decimal 12-hour (`5` = 5:00, `10.5` = 10:30, `2` = 2 AM/PM by context) on a 15-minute grid, optionally with an explicit meridiem (`7a`, `9.5p`) that pins the exact time — any time of day works. Bare In readings follow the rule `amFrom ≤ t < 12 → AM, else PM`; `amFrom` is `settings.amFrom` (Settings → "Morning starts at", default 9, `setAmFrom` in time.js). Always convert through `inAbsOf(parsed)` / `afterAbsOf(parsed, after)` / `atOrAfterOf(parsed, from)` (they honour the meridiem) and write back with `absToInRaw` / `absToOutRaw(abs, inAbs)` / `absToEdgeRaw(abs, open)`, which return the bare reading when it reads back to the same time and add the meridiem when it wouldn't (so a drag to 9:00p stores `9p`, not `9`). The keypad's typing goes through `parseClockEntry` (`530` → 5.5, `1045`, `5:3`, `17` → 5, minutes snapped to the quarter) and is stored as that decimal — `parseTime` only accepts `.25` steps (`5.3` is invalid), so scrub/stepper UIs can assume snapped positions. Everything resolves onto one absolute axis: `abs(t) = t >= anchorRaw ? t : t + 12`, where the anchor is the resolved global In (the shift "open"). A session spans < 12h. Display am/pm is a heuristic: anchors in [8, 12) read as morning opens.

### Resolution & closer rule (resolve.js)

Per person: `in = explicit || roleDefault || global.in`; `out = explicit || roleDefault || closeTime` (blank Out inherits the close time = resolved global Out). **Breaks:** `hours = out − in − brk`; in a pool a placed break (`brkAt`, resolved at/after their In) comes off the pool it falls in, an unplaced one off each pool in proportion to the time worked there (`poolParticipants`); a break outside the shift or as long as it is an error (tests/breaks.test.js). Closers: `closerOverride || out ≥ peak out across tipped staff` — ties share; support staff never auto-close. Pool windows: blank start = earliest resolved in, blank end = close time; `'srv'` / `'bar'` = latest server / bartender Out on shift (else that role's default Out, else close). A window whose edges are both derived may collapse to nothing (Mid when the servers stay to close) — that's an empty pool, not an error; a typed window must run forward.

### Tip split (shares.js)

Per pool: participants = staff whose role is enabled (or support if `includeSupport`) with overlap > 0; support's cut comes off the top, then `rate = (total − support cut) / Σ tipped hours`. Then once across all pools: `base = floor(Σ rawShares)`; remainder = Σ totals − Σ base; bonuses = manual overrides if any, else split among closers; leftover = chump. The Close Time sidebar, net-total ideal targets, and live calc are the same `computeShares` call with different inputs.

### Distribution engine (engine.js)

1. Preflight — cash covers payouts, enough small bills
2. Preferred path — proportional $100s/$50s, balanced sweep of lower denoms
3. DFS fallback — up to 100 paths, graded for evenness

On failure, `planMakeChange` picks the fix that takes the fewest bills out of the drawer: `planExchange` (pay everyone from the drawer as far as it goes, then trade the unused bills in ONE exchange for exactly the small bills the remainders need — e.g. "Trade 3 × $50 for 5 × $20 + 3 × $10 + 2 × $5 + 10 × $1") vs `suggestBreaks` (fewest single "break one bill" swaps, ≤3, iterative deepening; wins ties). `previewSmallBillTrades` is the last resort, reported as one net trade. Plans rank by cash exchanged → $100s traded (at equal cash, trade $50s and keep the $100s) → bills handed over → bills brought back → $10s brought back → drawer size; the exchange first consolidates what comes back (`consolidateGet`: two $5s → a $10, five $1s → a $5 while everyone is still paid exactly), so a swap asks for 1 × $10 rather than 2 × $5; the exchange places $100s/$50s with a DP that strands the least cash ($50s before a $100) so a $50 evens out an odd-tens payout instead of a $10.

Small-bill requirements (`getSmallBillRequirements`, used by preflight, the Bills card and the Close-time what-if) compute the $1+$5+$10 minimum with an exact DP over where the drawer's $100s/$50s can actually go — a $50 only saves a $10 if that payout has room for it after its $100s. $20s are assumed unlimited there; a $20 shortage shows as "larger bills don't divide evenly". The UI only shows the "small bills needed" card when $1/$5/$10 minimums are actually short (`smallBillsShort` in render/dist.js).

`distribute(people, bills, leftover)` → `{ byPerson: {id→bills}, remainderBills, poolAfter, error }` — pure, no mutation. The drawer comes from `drawerBills(pools, people, leftover)`: every pool's counted bills are kept as entered; the uncounted rest (`netTotal`) plus the register adjustment is filled with the bills the payouts need most (the $1 / $5 / $10s still short given where the counted $100s / $50s can go, then $20s) — `added` is that fill (Tips' "Best bills" card). A negative remainder (short more than the uncounted cash) comes off the counted bills, largest first; when that can't be exact, `note` asks for a recount.

## Persistence

- **Sessions** (`sessions.js`): every shift is its own session. The index `tippool_sessions` = `{ v, current, list: [{ id, name, date, created, saved, total, people }] }`; each session's snapshot lives at `tippool_s_<id>`. On first run the legacy single-session key `tippool_v1` becomes the first session (left in place, no longer written).
- Auto-saves the current session after every render (debounced with compute) and refreshes its index summary.
- Snapshot is `{ v: 4, saved, state }` — the state object directly.
- Switching sessions happens in place (no reload): flush the outgoing session, `store.replaceState`, invalidate staff/tips, re-render. `settings` are app preferences carried into whichever session opens (forced on if that session uses roles / several pools).
- Cash is one form (`entryMode: 'mixed'`): counted bills + the uncounted rest (`netTotal`) + a signed register `adjust` ("-50"). Older pools load through `normalizeCash` (persist.js): `perbill` keeps its counts and drops the unused net total, `nettotal` keeps the net total and drops the counts. `resolvePools` still honours an old mode if one slips through.
- v1–v3 snapshots (old DOM-serialized shape) migrate on load: bartender/server/support lists → one staff array, night cash → one pool; day-pool/cut data is dropped.
- Validate-or-discard: malformed data never crashes the app.
- Export (current session) / import (adds a new session and opens it) on Settings; a dated `.json` file, normalized to v4 on import.

## UI notes

- **Writing UI:** every view is a Preact component written with htm's `html` tagged template (reads like JSX: `html\`<${Card} flush>…<//>\``), built from `ui/pkit.js` and styled with Tailwind classes. Each area is re-rendered with the latest view model on every app render (`render(html\`<${View} vm=${vm} />\`, root)`); Preact diffs, so input focus, scroll and `<details>` state survive — no signatures, patch passes or focused-input guards. Handlers are functions calling `window.App.*` (`onClick=${() => App.tab('tips')}`); local UI state uses hooks (`useState`). Colour values are CSS variables in `css/app.css` (`--bg`, `--surface`, `--accent` … light in `:root`, dark under `prefers-color-scheme` and `[data-theme=dark]`); `index.html`'s `@theme inline` block names them for Tailwind (`bg-surface`, `bg-surface-2`, `text-ink-3`, `text-accent`, `bg-bar/14`, `rounded-card` …). In hand-written CSS or `style=` use the raw variable (`var(--accent)`), not `--color-*`. Lay screens out with the pkit building blocks so they stay consistent: `<${Section} title aside footer>` (small uppercase caption above a group, footnote under it; `Label` is the same caption standalone), `<${Card} flush>` holding `<${Row} lead title sub trail onClick>` list rows, `<${Banner} tone=ok|error|warn title sub onClick>` for status (children = extra content, e.g. the fix steps), `<${Stats} items>` for 2–4 figures in one block split by hairlines. A visual change to a repeated piece = edit its pkit component once. Tailwind's browser build scans the live DOM, so dynamic class names work; `<html>` gets `.ready` (main.js, a `hidden` probe) once the utilities have compiled, which un-hides the page. Note htm/Preact render `${0}` as "0" — guard numbers with `n > 0 && …`.
- **Clock:** every displayed time goes through `fmtTimeAbs` (time.js): "h:mma/p" by default, "HH:MM" when `settings.clock24` is on. Entry is unchanged — decimal 12-hour.
- **Navigation** (ui/nav.js, render/tabs.js): four **tabs** in the docked tab bar — **Home** · **Staff** · **Tips** · **Settings** (`#tb-*`, badges `#tab-sub-*`: staff count, tips total or `!` on an input error / bills that can't pay out). **Tabs change only by tapping** — there is no page swipe between tabs and no side panels. Tapping the current tab pops it back to its root page (or scrolls to the top). Inside a tab:
  - **Header** (`#hdr`, rendered by tabs.js) is **one compact row** (`--hdr-h` 3rem): a page with sub-tabs shows them there in place of its title (the tab bar already names the page); a page without shows its title (`.hdr-big`); then its actions (Home: Copy; Staff: Select / Done). A subpage shows ‹ Back (the page under it) · its centred title · its `actions`.
  - **Sub-tabs**: a `Seg` in the header — Home: Pay · Shift · Bills · Split; Tips: Cash · Drawer. A **sideways swipe** on the page steps between them (follows the finger, rubber-bands past the ends). Each sub-tab keeps its own scroll.
  - **Subpages**: a row can push a page in from the right (`pushPage`) over the stage (`#subpages`); **swipe right** or Back pops it. Subpages have no sub-tabs, so a sideways swipe on one only means back. Each tab keeps its own stack; switching sessions clears them (`resetNav`). Used for Home's person / pool pages and Settings' This shift / Sessions (This shift is also pushed onto Staff by Default times — `App.openDefaults()`).
  - Ignored by the swipes: sideways scrollers (`.overflow-x-auto`), text fields, the wheel, a held box (`dragFlags`), `[data-noswipe]`, while the keypad / keyboard is up or a sheet is open.
  - **Totals strip** (`#pipHud`, Staff and Tips only): one quiet line over the tab bar — Tips · Hours (or the person being edited) · Rate — with the would-be numbers in accent while an edit is previewed, and a row with **Undo · Apply** after a wheel / keypad edit (`App.reviewed`). Until the shift is complete Home and Tips › Drawer show `Blocked` (Home hides its sub-tabs then) — the close-out checklist. Staff and Tips end with an accent **`NextStep`**. Old snapshots' tab names map via `normalizeTab` (summary → home, payout → tips).
- **Settings** (render/settings.js): **This shift** (the current session's row → its own page: session name, an **inline calendar** with dots on days that have other saved sessions, the shift times as `KeyTime` cells — Open → Close then per role, remembered per shift type in `settings.shiftTimes` — support tip-out %, Export / Delete), **New session**, **All sessions** (→ the list: tap to switch; Edit → rename / delete) → **Appearance** (Theme Auto / Light / Dark, Display size) → **App** (Servers & support, Several pools, 24-hour time, Morning starts at) → **Show** (Staff timelines, Tips' best bills) → **Data** (Copy as text, Export, Import). Deleting the current session opens the next newest, or a fresh one.
- **Simple vs detailed** (`state.settings`, switches on Settings; shared by every session). `allRoles` off → one "On shift" section on Staff, no "Shared by" chips with one pool, This shift shows only the whole-shift times; new people are bartenders. `multiPool` off → no "+ Add pool" (can't be switched off while >1 pool exists). Compute ignores settings.

## CSS / design system

Tailwind utilities in the components do almost everything. `css/app.css` holds only what utilities don't express well, in `@layer components` so utilities always win:

- colour tokens (light / dark), Poppins `@font-face` (vendored in `vendor/fonts/`), the type scale (`.t-display` `.t-title` `.t-head` `.t-body` `.t-small` `.t-cap`), list groups (`.lgroup > .li`) and `.figures`,
- the page shell (header + `.icon-btn` / `.hdr-pill` / `.hdr-title`, `.page-title`, `.content` scroller, docked `.tabbar`, `.hud`, fill-screen),
- the stage and subpages (`.stage`, `.subpages` / `.subpage` + `.in`; `html.sub-open` while the current tab has one), and the totals strip (`.hud`),
- bottom sheets (`.sheet-backdrop` / `.sheet` slide-up, page-coloured with a grab bar; cards inside stay `surface`),
- the settings `.switch`, and bill tints: `[data-d="N"]` → `--dc`, used by `.denom` (banknote tag), `.billtag` (small pill) and `.bill-col` (bill-table heads).

- **Look:** the same design system as barlog (`~/Code/barlog`): iOS-style grouped screens, light by default and dark with the system (or forced from Settings → Theme). **Surfaces:** the page, subpages and sheets are `bg`; cards / list groups are `surface` (no borders, no shadows); controls inside them are `surface-2`; the picked segment is `raised`. Hairlines (`line`) only between list rows and under table headers. Frosted `--glass` only on the tab bar and sheet footers. Each tab opens with a big `t-title`, groups have small uppercase `t-cap` captions.
- **Colour roles — one job each:** `accent` = tappable / active (primary buttons, links, active tab icon, selected chips, a dragged time pill); `good` = rate / fine; **`money` = take-home amounts** (Summary's Tips column and Total, the Tips figure, Payout's Pay column and total, the Person sheet's take-home; support keeps `text-sup`); `bad` = closers and errors; `warn` = needs a look. Other figures are plain `ink`. **Person colours** (`--p1…--p8`, pkit `hueVar` / `hueIndex` / `hueTile`): every person gets a colour by their place among the named staff — their number tile (Summary, Staff), their Staff timeline, a dot by their name in Payout's envelopes — so a night of only bartenders still has colour; roles show as headings / dots. The Hours figure is teal (`--p3`). **Dark mode is the likely one at close**, so it's tuned for it: lifted inks (`ink-2` #ccd4df, `ink-3` #95a0b1), brighter accents / roles / bill tints, cards a step off the page with a faint hairline ring (`--card-ring` on `.lgroup`, `.figures`, `Card`). Roles `bar` / `srv` / `sup` (`ROLE_TINT` / `ROLE_DOT` in pkit.js) for role dots and badges; `--pool-2…4` (plus accent) colour the Summary pool bands. Bill tints `d100`…`d1` are only for bill sizes. Every colour has a light and a dark value — add new ones in all three places in app.css and name them in index.html.
- **Times:** pkit's `Clock` renders "5:45p" — a slightly smaller (0.8em) lowercase a / p, same weight (no ":00" unless `mins` is set — a column where some time has minutes; 24-hour has none). `bare` drops the a / p ("6", "12:30" — Summary's time pills, where the night says which); `DragTime`'s `alt` shows a word at rest instead of the time ("close").
- **Money:** `fmtMoney` (`$1,037`) or the kit's `Money()` (small "$"); tab badges use `fmtMoneyShort`.
- **Type:** Poppins everywhere (400/500/600/700, vendored), tabular numerals. Prefer the `.t-*` scale; weights stop at 600 except the page titles. Inputs ≥16px so iOS doesn't zoom.
- **Display size:** every size is in `rem` (Tailwind's scale, and arbitrary values written as `text-[1.25rem]`, never `px`; app.css too, except hairlines, media queries and the 480px column), so one root font size scales the whole UI. App settings → Display size sets `settings.size` (`s` / `m` / `l` / `xl` = 13.5 / 15 / 17 / 18.5px on `<html data-size>`, default `m`) — sized up for an iPhone held at arm's length at close. Write new sizes in rem (px ÷ 16) or they won't scale.
- **Gestures:** tap = edit / open (a **time** opens the keypad); **hold** a time = the wheel (Staff, Tips, This shift — never Home), and the thumb keeps turning it (slide, or lift and flick; Done / tap outside keeps it with Undo · Apply, ✕ puts it back); **hold** a −/+ button (`holdRepeat`) = keep stepping; **swipe sideways** on a page = its next / previous sub-tab (never another tab); **swipe right** on a subpage = back; swipe a sheet down = close. No row swipes, no edge drags.
- **Touch sizes:** `--tap` (2.75rem: chips, toggles, small buttons, tool chips — `h-[var(--tap)]`), `--row` (2.75rem: a Table row), `--row-lg` (3.25rem: total rows) in app.css; Seg is `sm` h-8 · `md` h-10 · `lg` h-11; header buttons (`.icon-btn`, `.hdr-pill`) 2.75rem (a thumb's view switch). Use the tokens rather than new heights.
- **Figures:** one look — `Figure` (value `t-head` over a `t-small` ink-3 label, optional `Delta` after the label) for `Stats`, `LiveStrip`. Changes in money are always `Delta` ("+$4" good / "−$3" bad, `.delta` in app.css), never hand-coloured text.
- **Sizing:** built for 375–440pt iPhones; `max-[400px]:` / `max-[374px]:` variants tighten small phones. Tap targets ≈44–48pt.

### Page shell, subpages & totals strip (fragile — read before touching)

- `<body>` is a `height: 100dvh` flex column: the header (`.hdr`) · the **stage** (`.stage`, `flex: 1`, `overflow: hidden`) holding the `.content` scroller and the subpages (`.subpages` — each `.subpage` is its own scroller, absolute over the stage, sliding in with `.in`). The tab bar is docked at the bottom: `--dock` = `--tab-h` (3.75rem) + the bottom safe-area inset — the totals strip, the bulk bar and toasts sit above it. The strip (`.hud`) is `position: fixed` and shows only on Staff / Tips (`html[data-page]`); `.content` and `.subpage` pad their bottom for it. The four tab pages are `.panel`s in `.content` (one `.active`; a sub-tab swipe moves it with inline `transform` / `opacity`, `.from-left` / `.from-right` animate the next one in). While the keypad is up the room to scroll a cell above it is a `::after` spacer, not padding — padding taller than the scroller would grow it and push the page up. Staff's bulk bar (`.bulkbar`, z 81) replaces the strip while `html.bulk-on[data-page=staff]`. Layers: subpages 15 (in the stage), strip 80, sheets 100, keypad 110, toast 120, wheel 140.
- The status bar style stays `black-translucent` (the header pads by the safe-area inset; the fill-screen fix below depends on it). Check that the status-bar text reads in the light theme on a phone.
- **Don't make `<body>` `position: fixed`.** In the iOS home-screen app that ties the page to a shortened viewport and the bar gets cut off.
- **Home-screen fill (`main.js`):** iOS can report a viewport shorter than the screen (e.g. 844 of 912pt). When detected, `html.fill-screen` sizes `<html>` and `<body>` to the real screen height (`--app-h`), the tab bar / strip / bulk bar / sheets switch to `position: absolute` inside that box, and the window is kept scrolled to 0. Add `?pwa` to the URL to force this in a desktop browser.
- **Zoom is locked:** viewport meta (`maximum-scale=1, user-scalable=no`), `html { touch-action: manipulation }`, and iOS `gesture*` events blocked in `main.js`. A zoomed page shifts the fixed bar.
- Verify layout changes on a real phone **from the home screen** (delete and re-add the icon to pick up new code) — desktop emulation doesn't reproduce the iOS viewport quirks.
